# Lightweight detector benchmark

측정 입력은 `bag_extract/20260806_130814`의 640x480 RGB8 영상 8,949프레임이다.
전체 bag을 순차적으로 읽어 디버그 이미지 생성 없이 순수 detector core 처리시간을
측정했다. 상세 원시 결과는 `lightweight_benchmark.json`에 있다.

## 성능

| 항목 | 결과 |
|---|---:|
| 카메라 FPS | 30.167 Hz |
| detector 평균 처리 성능 | 909.366 FPS |
| ROI crop 평균 | 0.0058 ms |
| 외함 탐색 평균 | 0.9774 ms |
| HSV 분류 평균 | 0.1107 ms |
| 전체 평균 | 1.0997 ms |
| 전체 p99 | 1.5196 ms |
| 전체 최대 | 2.8675 ms |
| 2-frame 확정 지연 중앙값 | 32.994 ms |

이 수치는 rosbag 역직렬화, DDS, GUI, JPEG 시간을 제외한 코어 측정값이다. 기본 실행은
JPEG가 꺼져 있고 QoS depth가 1이므로 30 Hz 입력 처리 예산 33.3 ms보다 충분히 작다.

## 해석

요청된 기본 ROI는 x=30~70%, y=0~50%다. 제공 bag의 근접 RED/YELLOW 구간에서 실제
신호등의 왼쪽 슬롯이 x=30% 경계 밖에 있기 때문에 RED 슬롯 픽셀은 코어에 입력되지 않는다.
LEFT 구간에서는 오른쪽 슬롯이 x=70% 밖으로 잘린다. ROI 밖을 처리하지 않는다는 설계 원칙과
고정 ROI를 동시에 지키면 이 프레임들의 올바른 4등분 분류는 불가능하다.

따라서 실제 차량에서는 튜너의 `Original / ROI` 창으로 4구 외함 전체가 ROI에 들어오는지
먼저 확인해야 한다. 본 기본값은 요청사항을 그대로 보존했으며, 정확도 수치를 높이기 위해
검증 중 몰래 ROI를 넓히지 않았다.
